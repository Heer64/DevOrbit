\section{Test environment}
\begin{itemize}
\item \textbf{Local:} Windows laptop, Node v22.16.0, npm 10.9.2, local MongoDB service. Backend tests use \texttt{MONGODB\_URI\_TEST} (a throw-away database per run);
      E2E uses \texttt{E2E\_MONGODB\_URI} and Playwright (Chromium), which starts its own API and a production build of the frontend.
\item \textbf{CI:} GitHub Actions (\path{.github/workflows/ci.yml}). Lint (Node 22), backend tests, frontend tests and build on Node 20 and 22 with a MongoDB 7 service, then E2E.
\item \textbf{Frameworks:} \texttt{node:test} + supertest + mongodb-memory-server (backend), Vitest + Testing Library + jsdom (frontend), Playwright (E2E).
\end{itemize}

\section{Exit criteria in detail}
\subsection{EC1: register, log in, edit the profile, create a project}
\begin{checkinfo}
Automated & \path{backend/test/auth.test.js} (7): register returns a session; passwords stored as salted bcrypt hashes; duplicate/bad emails and short passwords refused;
log in with the right password and fails with the wrong one; five wrong passwords lock the account; protected routes need a token; log out revokes the session on the server.\\
& \path{backend/test/profile.test.js} (13): bio 500 accepted, 501 refused; 10 skills accepted, 11 refused; photo exactly 2 MB accepted, one byte over refused (413);
non-JPEG/PNG refused (415); a file that only claims to be an image refused; replacing a photo deletes the old file; photo stored in MongoDB, not on disk. \\
& \path{backend/test/projects.test.js} (15): create stores name, description, domain and visibility and makes the creator Owner; name required; visibility must be Public or Private. \\
& \path{backend/test/projectCreate.test.js} (6) and \path{projectSetup.test.js} (7): domain must come from the agreed list; starting members added with roles; one bad starting member means nothing is created. \\
End to end & \path{e2e/tests/auth.spec.js}: a new user signs up, logs out and logs back in; a wrong password shows an error and stays on the login page.
\path{e2e/tests/role-permissions.spec.js} creates a project with a starting member through the real create form. \\
Result & \PASS{} -- all pass in the final run (Section~\ref{sec:results}). \\
\end{checkinfo}

\subsection{EC2: role rules work}
\begin{checkinfo}
Automated & \path{backend/test/permissions.test.js} (16 unit tests of the rules) and \path{projects.test.js}: a Viewer cannot change roles (403, nothing changes); a Contributor cannot add, change or remove members;
non-members get 403 on every members endpoint; the Owner can promote and demote; an Admin can manage only Contributors and Viewers; nobody can create a second Owner or change the Owner;
private projects are 403 for non-members. \\
End to end & \path{e2e/tests/role-permissions.spec.js} (added by the tester, PR \#51), two browsers: the Owner adds the Member as a Viewer; the Viewer sees no \emph{Add task} button,
a read-only message and no role menus; the Owner promotes them to Contributor; the Contributor can add a task but still cannot change roles. \\
Mutation check & With \texttt{canWriteTasks} temporarily allowing Viewers, the E2E test failed at the Viewer step (Figure~\ref{fig:mut}); the file was restored. So the test really detects a broken role rule. \\
Result & \PASS \\
\end{checkinfo}
