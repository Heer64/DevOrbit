\section{Deployment readiness (from this review)}
The code passes every test, but three settings are needed for the planned deployment (Vercel frontend, Render API, MongoDB Atlas):
\begin{itemize}
\item \textbf{Refresh cookie and two domains.} The refresh cookie is \texttt{SameSite=Lax}, so a page on \texttt{*.vercel.app} would not send it to \texttt{*.onrender.com}
      and users would be logged out on every reload. Plan: Vercel rewrites \texttt{/api} and \texttt{/uploads} to Render, so the API is same-site; socket.io connects to Render directly.
\item \textbf{Single-page routes.} A rewrite of all other paths to \texttt{index.html}, so reloading \texttt{/project/\ldots} does not give 404.
\item \textbf{Environment.} \texttt{TRUST\_PROXY}, \texttt{CLIENT\_ORIGIN}, a new \texttt{JWT\_SECRET}, a production GitHub OAuth App and webhook URL, mail provider, Platform Admin.
\end{itemize}
A smoke test of the deployed site (login survives a reload, live chat and task moves, file upload survives a redeploy, password-reset email, GitHub events, D1/D5 on Render) will follow the deployment.
