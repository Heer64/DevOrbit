\section{Tester items in detail}
\subsection{T1: CI on every pull request}
\begin{checkinfo}
Work & The tester created the GitHub Actions pipeline on 15 October (PR \#2) and, on 17 October, added the frontend tests and an end-to-end job (PR \#11).
On 16 November the lint job was added (PR \#49). Every pull request now runs lint, backend tests, frontend tests and the build on Node 20 and 22, then E2E. \\
Evidence & Every Sprint 3--6 pull request shows these checks; a red check was seen to stop E2E from running (Task 4 and Task 6 reports). \\
Note & The checks are not yet \emph{required} by branch protection on \texttt{main}, so a red check does not block the merge button (finding F1 in the Task 4 report). \\
Result & \PASS{} (with F1 open) \\
\end{checkinfo}

\subsection{T2: API tests for 403, 409 and validation}
\begin{checkinfo}
Tasks & \path{backend/test/tasks.test.js} (16): Viewer cannot create or edit (403); non-members cannot access a private project's tasks; the assignee must be a project member (US-22);
a task cannot be read, edited or deleted through another project's URL; a label over 30 characters is refused with 400 (US-21); progress recalculates when tasks are completed or reopened. \\
Kanban & \path{backend/test/kanban.test.js} (18): invalid status or a missing/bad version gives 400; a stale version gives \textbf{409} with the latest task and nothing is overwritten;
two simultaneous moves with the same version: exactly one wins; Viewers and non-members cannot change status. \\
Milestones & \path{backend/test/milestones.test.js} (9): Contributor and Viewer cannot create, edit or delete (403); input validated; progress from the milestone's tasks; tasks of another project cannot be attached. \\
Channels & \path{backend/test/channels.test.js} (13): \#general created automatically and only once; a Viewer gets 403 when sending but can read; non-members cannot read or post, even in a Public project; empty or too-long messages refused. \\
Result & \PASS \\
\end{checkinfo}

\subsection{T3: Viewer is read-only}
\begin{checkinfo}
API & 403 on task create/edit/delete/status, milestone writes and channel posts (tests above). \\
UI & \path{KanbanBoard.test.jsx}: ``Viewers see the board but cannot move cards''; \path{TasksPanel.board.test.jsx}: ``Viewers get a read-only board and a read-only task modal'';
\path{ChatPanel.test.jsx}: ``Viewers can read but get no composer''. \\
End to end & \path{e2e/tests/role-permissions.spec.js}: a Viewer sees no \emph{Add task} button and the read-only message; after promotion to Contributor they can add a task. \\
Result & \PASS \\
\end{checkinfo}

\subsection{T4: rollback and concurrent-edit conflicts}
\begin{checkinfo}
Rollback & \path{KanbanBoard.test.jsx} (13): ``puts the card back and shows an error when the server rejects the move'';
``rolls back after a 403 too (for example, role changed to Viewer meanwhile)''. \\
Conflicts & ``on 409 shows the conflict message and leaves the card in the server's column''; ``on 409 without a task in the body, fetches the latest task'';
\path{kanbanLogic.test.js} (10): live events are applied only when strictly newer, and a stale event does not undo a newer update. Backend: two simultaneous edits or moves with the same version, one wins and one gets 409. \\
Real time & \path{backend/test/realtime.test.js} (11): members (including Viewers) receive \texttt{task:updated}; rejected moves (409, 403) broadcast nothing; non-members never receive events;
a connection without a valid token is refused. \\
Result & \PASS \\
\end{checkinfo}

\subsection{T5: end-to-end demo flow}

``editing a task label is saved''. \path{dashboard.spec.js}: a task due tomorrow and assigned to me appears on the dashboard; completing a task updates the ``Tasks completed'' card. \\
Result & \PASS{} (22/22 E2E tests in the final run) \\
\end{checkinfo}
