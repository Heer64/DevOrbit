\section{The defect}
The seed (Sprint 1 plan line A, \path{backend/src/seed/seedData.js}) fills a development database with demo accounts
(\texttt{@seed.devorbit.test}) and two projects. \texttt{--reset} is meant to remove the demo data and seed again, without touching real users.
\texttt{removeSeedData()} deleted only the demo users, the projects they own, and those projects' tasks, milestones, messages, channels and activity
(plus follows and direct messages, added in Sprints 5 and 6).

Testers use the demo accounts in the app. Everything else they created stayed behind after a reset, pointing at users and projects
that no longer existed: decisions, docs, task comments, files and their bytes in GridFS, invitations, join requests, notifications,
GitHub connection records, posts and their images, votes, reports, sessions, password reset links and profile photos.
These orphans appear as broken entries and wrong counts (for example, a real post kept a vote from a deleted demo account).

\subsection{What \texttt{--reset} removes now}
\begin{enumerate}
\item \textbf{Inside the demo projects:} tasks, milestones, messages, channels, activity, decisions, docs, task comments, invitations,
join requests, notifications, project files (and their bytes in GridFS bucket \texttt{projectFiles}), portfolio stats, GitHub connection,
feed-key and OAuth-state records. The demo projects are removed from the webhook delivery log, but the deliveries themselves are kept.
\item \textbf{Made by the demo accounts anywhere:} their posts (with images in GridFS bucket \texttt{postImages}) and the votes and reports on them;
their votes on real posts, after which each affected real post is \textbf{recounted} (\texttt{recountPostVotes}) so its score stays right;
their reports, vote and post rate-limit logs, portfolio stats, notifications to or from them, invitations, join requests, sessions,
password reset tokens (Sprint 6 M1, \#48), OAuth states, follows, direct messages and profile photos (GridFS bucket \texttt{avatars}).
\item \textbf{Never touched:} real users, real projects, and a real user's own notifications.
\end{enumerate}
A GitHub webhook that a tester created for a demo project is not removed on GitHub, because the seed works offline. The README says so.

\subsection{T4: manual run on Windows}
\begin{checkinfo}
Steps & In \texttt{backend/}: \texttt{npm run seed}, then \texttt{npm run seed -- --reset} (Windows PowerShell 5.1). \\
Expected & The first run seeds; the second prints ``Removed the old demo data: 5 users, 2 projects'' and seeds again. \\
Actual & The first run seeded 5 users (including the Platform Admin from Sprint 6 M8), 2 projects and 9 tasks. The second run answered
``Seed accounts already exist. Run with --reset to recreate them'': the flag never reached the script (Figure~\ref{fig:ps}). \\
Cause & Windows PowerShell treats a bare \texttt{--} as ``end of parameters'' and drops it when it runs npm's PowerShell shim (\texttt{npm.ps1}).
npm then receives \texttt{run seed --reset}, takes \texttt{--reset} as an option for itself, and does not pass it to \texttt{seed.js}.
The same command works in Git Bash, macOS and Linux. \\
Workaround & \texttt{node scripts/seed.js --reset}, or \texttt{npm run seed '--' --reset} (quoted). \\
Result & Seeding \PASS; \texttt{--reset} through npm in PowerShell: observation \textbf{O7} \\
\end{checkinfo}

\section{Conclusion}
\texttt{--reset} now leaves no orphaned data behind. Everything created with the demo accounts or inside the demo projects is removed,
including stored file bytes, images and profile photos, and real posts keep correct scores. Real users and projects are unchanged.
The fix is covered by a new regression test, and the full suite, lint and CI pass. It was merged as \texttt{12cc67a}.
One documentation gap remains for Windows users (O7).
