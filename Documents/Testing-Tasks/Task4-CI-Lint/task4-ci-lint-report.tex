\section{Why this change}
ESLint was added in Sprint 1 (\texttt{eslint.config.mjs}, root scripts \texttt{lint} / \texttt{lint:fix}), but
\path{.github/workflows/ci.yml} only ran the backend tests, the frontend tests, the frontend build and the Playwright E2E tests.
Lint therefore depended on each developer remembering to run it, and a pull request with lint \emph{errors} could still go green.
The Sprint 1 plan (line A) and NFR-31 ask for the lint rules to be \emph{enforced}, not just available.

\subsection{The new job}
\begin{Verbatim}[fontsize=\small,frame=single]
  # Sprint 1 plan line A / NFR-31: lint rules are enforced, not just available.
  # Runs once (not per Node version) and needs no database, so it is quick.
  lint:
    name: Lint (ESLint)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: package-lock.json
      - name: Install root dev tools (ESLint, Prettier)
        run: npm ci
      - name: Lint
        run: npm run lint
\end{Verbatim}

\subsection{Design decisions}
\begin{itemize}
  \item \textbf{A separate job, not a step in the test job.} The test job runs twice (Node 20 and 22) and starts a MongoDB service.
        Lint needs neither, so it runs once and finishes in about 10 seconds. It also shows as its own check, so a reviewer sees at once
        whether a PR failed on style or on tests.
  \item \textbf{Errors fail, warnings do not.} ESLint exits with code 1 only when there is an error (for example \texttt{no-debugger},
        \texttt{no-undef}, \texttt{eqeqeq}), and GitHub Actions fails a step on a non-zero exit code. Rules such as
        \texttt{no-unused-vars} are set to \texttt{warn} in \texttt{eslint.config.mjs}, so they are shown but do not block.
  \item \textbf{Root lockfile.} ESLint and Prettier are dev dependencies of the root \texttt{package.json}, so the job installs with
        \texttt{npm ci} from the root \texttt{package-lock.json} and caches it.
\end{itemize}

\section{Incident during the task: a workflow that ran nothing}\label{sec:incident}
\begin{checkinfo}
Symptom & After the first push, PR \#49 showed \textbf{Checks 0} and ``Ready to merge'' (Figure~\ref{fig:zero}): a false green. \\
Cause & While editing \texttt{ci.yml}, the line \texttt{- name: End-to-end tests} had been commented out (Figure~\ref{fig:commented}).
Its \texttt{working-directory} and \texttt{run} lines then belonged to the step above, which already had both keys.
A step with duplicate keys makes the whole workflow file invalid, so GitHub ran \emph{no} job at all, not even the old ones. \\
Fix & Restored \texttt{main}'s file (\texttt{git checkout main -- .github/workflows/ci.yml}), added the lint job again, saved without formatting,
and checked with \texttt{git diff main} that only lines were added (commit \texttt{3da84ec}). The YAML was also checked for duplicate keys. \\
Side issue & VS Code's formatter changed \texttt{MONGOMS\_DISABLE\_POSTINSTALL: '1'} to \texttt{"1"} on save. Harmless, but unrelated to the PR;
reverted, and the file is now saved with \emph{File: Save without Formatting}. \\
Lesson & A broken workflow does not fail, it simply does not run. Always check that the expected checks \emph{appear} on a PR,
and compare workflow edits with \texttt{git diff main} before pushing. \\
\end{checkinfo}

\section{Conclusion}
CI now runs ESLint on every push and pull request to \texttt{main} and \texttt{develop} as a separate, fast \emph{Lint (ESLint)} check.
The latest code passes (0 errors), and the negative test shows that a lint error turns the check red, both locally (exit code 1) and on the PR.
The PR's net change is 20 added lines in \texttt{ci.yml}. To make the rule fully \emph{enforced}, the repository owner should make the
checks required on \texttt{main} (F1).
